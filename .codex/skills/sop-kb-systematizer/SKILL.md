# SOP KB Systematizer

把零散 SOP、制度、流程说明和知识库材料整理成可维护、可检索、可阅读的公司知识库。默认输出一份 Markdown 和一个单文件 HTML。

## Core Principle

先设计知识结构，再写页面内容。不要把所有信息堆成一个长页面；先拆成主题、分类和虚拟子页面，再让 Markdown 与 HTML 共用同一套信息架构。

## Workflow

1. 确认使用对象、知识库范围、材料来源、是否对外可见、更新频率和保密边界。
2. 盘点输入材料，按主题、流程、角色、场景或部门归类；重复内容合并，冲突内容标记为 `待确认`。
3. 先输出或内部拟定页面地图：`首页`、一级分类、二级子页面、关键索引和待补资料。
4. 将每个 SOP 拆为独立虚拟页面，避免单页过长；同一页面只承载一个清晰主题或流程。
5. 生成 Markdown 总览稿，用于审阅、留档和后续维护。
6. 生成单文件 HTML：把页面数据、样式和交互都放进一个 `.html` 文件，使用嵌套式导航模拟子页面。
7. 交付前检查 Markdown 与 HTML 的标题、目录、页面顺序、待确认项和版本信息是否一致。

## Markdown Output

默认生成中文 Markdown，结构如下；用户有模板时优先沿用用户模板。

```markdown
# <知识库名称>

## 使用范围

- 适用对象：<团队/角色>
- 覆盖范围：<SOP/制度/流程/知识库边界>
- 材料来源：<文件、访谈、会议纪要、飞书文档等>
- 更新时间：<日期>

## 页面地图

- 首页：<知识库定位与快速入口>
- <一级分类>
  - <子页面一>
  - <子页面二>

## 首页

### 快速入口

| 场景 | 应该查看 | 说明 |
| --- | --- | --- |
| <场景> | <页面名> | <一句话说明> |

## <一级分类>

### <子页面名>

- 适用场景：<什么时候用>
- 负责人/维护人：<角色或待确认>
- 输入材料：<需要准备什么>
- 标准流程：
  1. <步骤>
  2. <步骤>
- 输出结果：<产物或完成标准>
- 常见问题：<FAQ>
- 待确认：<缺口、冲突、需要补资料的点>

## 待补充与待确认

- <不能从材料中确定但影响使用的内容>

## 版本记录

- <日期>：<本次整理范围>
```

## Single HTML Output

默认生成一个可直接打开的 `.html` 文件，不依赖外部 CDN、构建工具或服务器。除非用户另有要求，不要拆成多个 HTML 文件。

HTML 必须具备：

- 单文件结构：CSS、JS、页面数据都内嵌在同一个 HTML 文件里。
- 嵌套式子页面：使用页面数据、`data-page`、hash route 或等价方式模拟 `首页 / 分类 / 子页面`。
- 响应式布局：桌面端使用左侧目录树 + 主内容区；手机端使用顶部栏 + 可展开导航或抽屉。
- 清晰导航：目录树、面包屑、当前页面高亮、返回上级分类。
- 快速查找：至少提供页面标题和正文关键词搜索，结果能跳转到对应虚拟页面。
- 可维护数据：页面内容集中放在清晰的数据结构中，方便后续增删子页面。
- 可读性：正文宽度受控，表格可横向滚动，长流程拆成步骤或卡片，避免信息挤压。
- 可访问性：按钮有明确文本或 `aria-label`，键盘可操作，颜色对比足够。
- 打印友好：至少保证主内容打印时可读；不需要打印导航。

推荐 HTML 页面数据形状：

```javascript
const pages = [
  {
    id: "home",
    title: "首页",
    parent: null,
    summary: "知识库总览与快速入口",
    tags: ["总览"],
    content: "<section>...</section>"
  },
  {
    id: "onboarding-account",
    title: "账号开通 SOP",
    parent: "employee-onboarding",
    summary: "新员工账号开通流程",
    tags: ["入职", "账号"],
    content: "<section>...</section>"
  }
];
```

## Content Rules

- 保留事实、推断和待确认边界；材料没有明确说明时写 `待确认`，不要编造负责人、时限、制度依据或流程步骤。
- 如果原始材料互相冲突，列出冲突点和来源，不自行裁决。
- SOP 页面优先写清楚：适用场景、触发条件、输入、步骤、输出、负责人、完成标准、异常处理和常见问题。
- 知识库页面优先写清楚：概念定义、适用范围、关联页面、示例、注意事项和维护人。
- 对所有人可用的知识库，避免过度使用部门黑话；必要术语先给一句解释。
- 对外可发版本要删除内部判断、聊天口吻、敏感信息和未确认内容。

## Quality Checklist

- 是否先有页面地图，而不是直接生成长文。
- 是否至少输出一份 Markdown 和一个单文件 HTML。
- HTML 是否在手机端和电脑端都能阅读和导航。
- 是否有嵌套式导航、子页面、当前页面高亮和搜索。
- 每个 SOP 是否有输入、步骤、输出和完成标准。
- 待确认项是否集中列出，方便负责人补资料。
- Markdown 与 HTML 的页面结构和版本信息是否一致。
