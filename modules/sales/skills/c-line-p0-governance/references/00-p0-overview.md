# P0 Overview

## 目标

跑通 C 线主管治理的最小闭环，让主管先看到销售事实、连续工作周期、客户推进风险、主管干预 draft、系统健康与异常记录。

## 输入

- C00 治理规则。
- C01.0 销售个人治理表索引。
- B 线 active 日记录和 blacklight_output。
- A 线 latest_snapshot / ledger。
- D 线反馈引用。
- E 线行动地图引用。
- A/B/C/D/E 运行日志。

## 处理步骤

1. 由 `C-BL00` 统一读取治理规则、索引和运行状态。
2. 由 `C-SK01` 维护销售个人 C01 表索引。
3. 由 `C-SK02` 将 B 线 active 日记录同步为 `C01.sales_xxx` 的 `daily_fact`。
4. 由 `C-SK03` 基于 `daily_fact` 生成滚动周期摘要。
5. 由 `C-SK04` 读取 A/B 必要证据，识别客户停滞、高意向、临门一脚和风险候选。
6. 由 `C-SK08` 将风险候选转为主管干预 draft。
7. 由 `C-SK16` 记录字段缺失、同步失败、权限异常、黑灯异常和公共表写入冲突。

## 输出

- C01.0 销售个人治理表索引状态。
- C01.sales_xxx `daily_fact` 与滚动摘要。
- C01.2 客户长周期推进记录。
- C01.5 主管干预 draft。
- C07 调度、系统健康与异常记录。

## 边界

- 不修改飞书 Wiki/Base/Sheets 结构。
- 不新增字段，不改字段选项。
- 不复制 A 线客户完整档案。
- 不修改 B 线过程层。
- 不替代 D/E 的策略权重调整。
- 不把 AI 建议当成人工确认结论。
- 不允许多个销售黑灯并发写公共治理表。
- 公共表统一由 `C-BL00` 调度写入。

## 验收

- P0 链路可按 `总控 -> 索引 -> 日事实 -> 周期摘要 -> 客户风险 -> 干预 draft -> 异常记录` 串行解释。
- 所有输出都有来源引用。
- P0 输出不包含训练闭环、SOP 发布、产品反馈包或总经办自动提交。
